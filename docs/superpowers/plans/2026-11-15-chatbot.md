# Chatbot hỏi đáp website — Kế hoạch triển khai

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Thêm chatbot (Grok qua cổng LiteLLM hiện có) ở góc dưới bên phải website, trả lời chỉ dựa trên dữ liệu công khai của trường, có FAQ xã giao có sẵn và chống prompt injection.

**Architecture:** Backend FastAPI module `app/modules/chatbot/` gồm các hàm thuần (guard, FAQ, prompt, output guard) dễ test + lớp điều phối `ChatbotService` + 1 endpoint portal. Ngữ cảnh = khối lõi (khoa/chương trình/cán bộ, cache TTL) + top‑k bài viết tìm theo từ khóa. Lịch sử do server giữ trong Redis. Frontend Next.js thêm `ChatWidget` (logo trường, câu hỏi gợi ý) gắn ở layout.

**Tech Stack:** Python/FastAPI/SQLAlchemy async, pytest (`asyncio_mode = "auto"`), Redis (`app.shared.redis.get_redis`), `AIService` (`app/shared/ai/service.py`), LiteLLM (`omniroute/config.yaml`); Next.js 16 + TypeScript + axios (`src/shared/api/axios-client.ts`), lucide-react.

**Spec:** `docs/superpowers/specs/2026-11-15-chatbot-design.md`

## Global Constraints

- Khóa xAI chỉ nằm ở biến môi trường `XAI_API_KEY` của cổng LiteLLM; không commit khóa, không để ở frontend.
- Chỉ dữ liệu công khai: đơn vị `is_active`, chương trình `is_active` và `is_published`, cán bộ `is_active` và `is_visible`, bài viết đã xuất bản (`list_all_articles_portal` đã lọc).
- Bot không có công cụ/tool; chỉ sinh văn bản. Client không gửi được lịch sử (`assistant`/`system`).
- Giới hạn câu hỏi 500 ký tự; lịch sử ≤ 10 lượt, hết hạn 30 phút; khối lõi cache 5 phút; `max_tokens` trả lời 500.
- Model chính Grok (`grok-chat`); khi Grok lỗi/hết hạn mức tự chuyển sang Groq (`llama-3.3-70b`) qua `router_settings.fallbacks` của LiteLLM, không dự phòng sang nhà cung cấp khác. Hai model phải cùng qua bộ kiểm thử nghiệm thu.
- Trả lời theo ngôn ngữ câu hỏi (vi/en); không streaming ở bản đầu.
- Nút chat dùng `public/images/logo-192.png`; nút Messenger hiện có dời lên trên nút chat.
- Frontend: đọc `node_modules/next/dist/docs/` trước khi viết code Next (xem `AGENTS.md`). Frontend chưa có test runner: kiểm bằng `npx tsc --noEmit`, `npm run lint` và thao tác trình duyệt, không thêm framework test.
- Commit message thường, không có dòng attribution Claude.

## Review Focus

- Câu hỏi rỗng/chỉ khoảng trắng/chỉ emoji → trả lời nhờ nói rõ, không gọi model, không lỗi 500 (Task 2, 7).
- Chuỗi Unicode lạ (zero‑width, ký tự điều khiển, chữ "lookalike" như `ｉｇｎｏｒｅ`) không lách được bộ lọc (Task 2).
- Khớp FAQ quá rộng nuốt câu thật (ví dụ "chào" trong "chào mừng tân sinh viên thế nào?") (Task 3).
- Redis lỗi/mất kết nối → vẫn trả lời (không lịch sử) thay vì 500 (Task 5, 7).
- Model lỗi/timeout → trả câu xin lỗi cố định, không lộ chi tiết lỗi (Task 7, 8).
- `session_id` giả (quá dài, ký tự lạ) không tạo khóa Redis tùy ý (Task 5, 8).

### Task 2: Bộ lọc đầu vào (`guard.py`)

**Files:** Create `app/modules/chatbot/guard.py`; Test `tests/chatbot/test_guard.py`

**Interfaces:**
- Produces:
  - `normalize_text(raw: str) -> str` — NFKC, bỏ ký tự điều khiển và zero‑width (`\u200b-\u200f`, `\u2060`, `\ufeff`), gộp khoảng trắng, `strip()`.

### Task 3: FAQ và xã giao (`faq.py`)

**Files:** Create `app/modules/chatbot/faq.py`; Test `tests/chatbot/test_faq.py`

**Interfaces:**
- Consumes: `fold` từ Task 2.
- Produces:

  - `detect_faq(text: str) -> FaqIntent | None` — so khớp **toàn câu**: `fold(text)`, gộp chữ lặp ≥3 lần thành 1 (`hiiii→hi`), rồi so với tập cụm của từng intent; cho phép đệm `ạ`/`nhé`/`bạn`/`ơi`/`a`/`nha`/`please`.
